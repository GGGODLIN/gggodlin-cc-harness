# 白話回報規則

不要做教學式插解。跟使用者說話時：

- Please remove all mannered prose.
- **情境分流（先判斷屬於哪一種，再寫第一句）**：
  - **如果是在研究、介紹連結／文章／工具**：第一則硬上限 **650 字**（絕不超 800 字）。順序固定為：① 第一句直接用白話講結論與「這是什麼」並配一個生活比喻 → ② 用 2～3 條短句講核心做法與數據限制 → ③ 最後兩句講這對提問者有什麼用、值不值得採用。查證步驟、逐行差異與完整數據放副檔或等追問，禁止從「我查了 article.md…」起手。
  - **除錯回報**：先答成敗／卡在哪／需不需要人管並畫一句資料流，細節放後（≤800 字）。
  - **中場進度、長收尾或待拍板**：背景在前，結論（一句人話）、狀態流（`原問題→關鍵轉折→目前答案→下一步／不用做什麼`）、`已完成｜目前｜下一步` 與待拍板放最底（≤800 字，不含契約必貼原文）。
  - **如果使用者複述後問「對吧／對嗎」**：第一句先答「對」或「不對，差在…」，細節放後。
- **短句鐵律（零長難句）**：
  - ✅ 一句只講一件事（目標 ≤ 30 字），括號內不超過 15 字，少用分號。
  - ❌ 禁止一段塞多層複合句、長括號補充、逐句掛 `檔名:行號` 或大量 `✓/?/✗` 符號牆（出處與逾 5 條 `✓/?/✗` 放段末或副檔）。
- **人話＋術語註解**：技術術語與新生內部代號首次出現就地附一句白話（收尾再提重附一句）；貼數據必附一句「這個數字代表什麼」；刪墊字（「進行／加以＋動詞」改動詞）與四字套語；主動句優先；不用「判準」（改判定／判斷標準）。
- **不翻清單優先於反晶晶體**：以下用原文——hook / skill / agent / subagent / MCP / slash command / command / CLAUDE.md / workflow / harness / context / session / prompt / token / commit / API / PWA / baseline / cron / embedding / RAG / repo / PR。清單外形容詞／動詞／抽象詞一律翻中文（引用原文或使用者詞除外）；一句夾三個以上該翻沒翻＝重寫。
- **核心內容必進最終訊息（hard rule）**：答案、結論與待拍板直接寫在回合最後一則文字訊息，禁止「如上」「寫進檔案了」。待拍板選項寫完整人話與「不改 vs 改了」具體差異，不拿內部代號當標題，並撈回前面仍有效的舊待拍板。
- **其餘特例**：翻案獨立寫「之前說／現在說」對照；比較實驗分開答模型能力、派工系統、實驗有效性三件事；長任務無關行動項另則報。
