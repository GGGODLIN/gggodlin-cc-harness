# E2E 行為契約

先確認要保留的行為，再驗產品；目前 code 的結果不是正確答案。人的決定、案例內容和受測版本分開保存，未來合併上游仍用原預期找差異。

## 入口與工作種類

模型可呼叫本 skill；正式父邊是 e2e-route，手動入口是 /e2e-contract。自然語言直接交入時先呼叫 `Skill(e2e-route)` 並結束，不先寫測試或操作 app；這是選用指引，不是硬性攔截。

1. route 正式交入後，使用 `work-kind=contract` 與本題已選工具。若交接缺工具或原任務，就停止回報，不再回 route 補救。
2. 手動交入且未選工具時，把原任務與 contract 工作種類交給 `Skill(e2e-route)` 一次並結束。已有本題有效選擇就沿用；環境阻塞不等於改選工具。
3. 本題已有契約與確認紀錄就接第 3 步；沒有則接第 1 步。新的獨立任務不繼承上一題確認。

## 1. 定範圍與來源

1. 從指定行為、補丁決策、PR／commit 或差異範圍，列本次保護清單與排除；相關上游行為只作必要前置，不擴成全專案巡檢。查得到的來源自己查，無法定位者列未納入。
2. 先讀人寫文件／決策原話，再查 code；標示文件明載、既有決策、code 推測、衝突與未知。fork 刻意偏離上游的行為交人決定，不以新版文件自動撤回補丁。
3. 如果要建立契約，就在寫候選材料前讀 [契約模板](/skills/e2e-contract/assets/contract-template.md)，按 context 中的 repo 慣例選資產位置；只記憑證名稱／指位，不保存值。

做完：範圍有來源或未知標記，未納入項目不算覆蓋。接第 2 步。

## 2. 提案例，等人確認

1. 每案寫 ID／語義版本、保護的行為、前置條件與資料分支、動作、可觀察預期、必要觀察點與不可繞過部位。工具不能驗的條件列未驗證，不用較鬆斷言替代。
2. 保存每案當時展示的確認內容快照與指紋，來源、工具設定另記；用既有雜湊工具，不寫新的 approval 工具。快照只存提案，不含尚未發生的批准。
3. 按使用者慣例展示待拍板項，請有權決定行為的人確認子集、版本、允許環境與操作。確認行為不附帶安裝、改產品、發布或部署授權。
4. 提案後停止，收到人的下一回合才接第 3 步。skill 建立批准、工具 a/b、agent 自述或文件 approved=true 都不是本次案例確認。

做完：候選版本與待確認項可對回；確認前沒有 setup、實跑、探索 app 或改產品。

## 3. 核對確認與續接

1. 自然語言確認／續做仍由 route 交入，不恢復懸空呼叫堆疊。核對人的原話來源、權責、案例 ID／版本、當時展示內容與本次操作範圍；不足就只問缺口並停，不靠標籤自批。
2. 只取已確認且允許操作的子集。用內容指紋對照快照；重要前置條件、資料分支、動作、預期或觀察點改變就另立版本，只重確認受影響案。純定位／接線變更記理由，不作廢其他案。
3. merge 改變 code／build 不會使原預期失效。改選工具保留案例與確認；新環境改變案例意義或權限範圍時先處理差額，不默默改期待。

做完：子集、內容版本與操作範圍明確；空子集停在待確認。接第 4 步。

## 4. 交給選定工具

1. 如果子集可執行，就在任何 setup／寫測試／實跑前讀 [共同執行契約](/skills/e2e-contract/references/execution-contract.md)。
2. 用 `mode=contract` 交入原任務、契約位置、子集與版本／指紋、確認原話來源、操作範圍、本題工具及 create 或 rerun 目的。這是提示內容的本地契約，不是新增平台欄位。
3. TesterArmy 呼叫 `Skill(e2e-tester-army)`；Playwright 呼叫 `Skill(e2e-explore-then-batch)`。註明由 e2e-contract 正式交入，不冒充 route／手動，不平行啟動另一套。
4. 子 skill 按共同契約保存；不完整交接停止，不回 route 重試或降級普通模式。

做完：只交已確認子集，工具來源與模式可辨識。接第 5 步。

## 5. 保存與回報

1. 如果取得結果，就在保存前讀 [執行紀錄模板](/skills/e2e-contract/assets/run-template.md)。測試留在既有位置，歷次結果存獨立副本，不只指 runner 下次會覆寫的預設檔。
2. 分開記材料保存、測試可執行性與產品符合程度。初次已不符列既存差異，不稱 merge 回歸；未執行、阻塞、失敗與通過逐案區分，不靠 skip／預期失敗／弱斷言湊綠。
3. 回報範圍、案例版本、實際目標、差異與未驗部分；其他問題另記，不擴修。執行紀錄是純 log，不加獨立整理門檻。

做完：每個交入案有狀態與證據，未確認案仍待確認。沒有真 SDK／產品證據就明寫未驗證，不把模型決策單元當真 E2E。
