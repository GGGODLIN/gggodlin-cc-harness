# 共同執行契約

只供 e2e-contract 的 `mode=contract` 正式交接。普通探索不走本分支；這些是模型指引，不是平台的機械授權或防竄改保證。

## 1. 進入前核對

1. 在 setup、探索 app、寫測試或實跑前，核對原任務、所選工具、本題契約位置、已確認子集、內容版本／指紋、人確認的原話來源、受測環境及允許操作。只有 mode、approved=true 或上層說確認過都不足。
2. 讀契約及人確認的內容快照，對照當前案例實際內容。子集不得含未確認或語義已變案；操作不可超過已批准前置條件。不足就回報交接錯誤並停止，不回 route 重試、不降級普通模式。
3. 分開案例版本、來源 code／測試版本、此次實際 app/build；工作目錄的 commit 不等於受測 server。不能確認受測版本就揭露，不宣稱這次 merge 已保護補丁。

做完：合法子集與範圍明確；接第 2 步。

## 2. 使用工具，不重建預期

1. 沿用專案已有測試、fixture 與資產位置。rerun 先執行對應既存測試，不重新探索／推導預期／固化；只有已確認且缺測試的案才生成工具專用腳本。
2. 在所選工具的必要操作前讀該工具的本地 setup／writing／running／debugging reference 或專案既有設定，遵守已載入的 repo 規則、安裝限制與 browser route。授權或設定不足就阻塞，不自動換工具或改全域設定。
3. 腳本映射案例 ID／版本、動作與必要觀察點。精確值用可對照的斷言；不能把「指定項目不存在」換成「畫面正常」仍算同案。工具無法表達者記未驗證。
4. fixture 只替代案例允許的部分，不裁掉不利資料分支、不預先產出理想結果、不繞過受測補丁；期待不能從同一受測實作或本次觀察反算。

做完：測試與案例語義對應、受測邊界未弱化；接第 3 步。

## 3. 執行與失敗分類

1. 在允許範圍執行最接近的測試，記命令、target／build、資料條件、exit code 與逐案結果。非冪等 live 操作仍沿既有授權與 one-shot 規則，不用自動重跑掩蓋結果不明。
2. 環境、SDK、定位或測試接線錯誤與產品不符分開。可修接線而不改已確認語義；重要條件或觀察方式需改時先交回 e2e-contract，只重確認受影響案。沒有新改動不重跑同一驗證。
3. 如果到達必要斷言且產品不符，就保存原斷言與實際差異，不改 expected、skip、預期失敗、timeout／retry 或 fixture 湊綠；不因普通 Workflow 的「跑綠才固化」拒絕保存此分支的材料。
4. 不自行修產品；另有明確授權才走最小修正。首次已不符標既存差異，不能稱 upstream merge 新造成的回歸。

做完：每案有未執行／阻塞／失敗／通過之一，結果不明與未驗條件有原因。接第 4 步。

## 4. 保存與交付

1. 保存腳本、案例映射、工具版本／設定或 lockfile 位置、重跑命令與所需環境變數名稱；不存憑證值。TesterArmy 與 PW 的腳本不需互跑，也不搬掉另一套資產。
2. 用 [執行紀錄模板](/skills/e2e-contract/assets/run-template.md) 存本輪獨立紀錄與證據副本，不只引用會覆寫的 runner 預設輸出。這是純 log，不加新帳本門檻。
3. 分開報材料是否保存、腳本本身的語法／實跑證據、產品結果。已實跑但 assertion 失敗的測試仍可留作回歸材料；只有探索或模擬骨架就標草稿／可執行性未驗，不聲稱已固化。
4. 本契約分支到此結束，不接普通模式的綠燈固化、自由改預期、批次修錯或自動整合。一般衛生檢查與最近測試仍照 repo 規則，但不疊新的每次 auditor；不降低原普通模式的 Self-Verify。

做完：交接子集都有材料狀態、產品狀態、來源與未驗項；回傳 e2e-contract 保存與回報，不自行呼叫 route。
