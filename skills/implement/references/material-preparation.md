# 實作派工材料 trial

只替 implement 準備材料區；原 skill 負責完整票文、測試模式、權限、控制條款與既有執行器。清單可重用，是為了少搬相同原文；首次選材、摘錄同步與補送仍是成本，收益留待自然任務觀察。

1. **先確認適用與範圍。** 沿用主流程的 Main scope 差額檢查。如果同任務已有材料清單，或已知後續會再次派工，就走下步；只有一次交付且沒有清單時沿原路，不為湊 trial 新建摘錄。清單只決定讀哪裡；最新文件不代表內容已批准。來源改版或批准狀態不清時，main 先對回真人授權，排除未批准部分或先釐清，不把較新的內容自動變成工作範圍。完成條件：本次範圍與適用分支明確。
2. **沿用原目錄列材料。** 在原任務目錄建立或更新 `materials.json`，只列 main 已確認必要且可交給實作者的文件；原檔不搬、不自動掃描目錄。相對路徑以清單所在目錄解析，也接受絕對路徑。如果用既有摘錄，就在重用前核對原文是否變動；重新讀摘錄不會更新摘錄內容。工單若混有其他票與完工紀錄，完整當票由原 skill 提供，別為組稿再造一份票。完成條件：清單只含本次材料；選材與摘錄責任仍在 main。

   ```json
   {
     "task": "本任務明確識別",
     "materials": [
       { "file": "spec.md", "roles": ["implement"] },
       { "file": "design.md", "roles": ["implement"] }
     ]
   }
   ```

3. **組稿再填入 prompt。** 新派工或需更新材料的續派前，執行下列命令；以目前載入的 skill 目錄定位腳本，不重寫組稿程式。只有 exit 0 才讀輸出，將原文材料區放入本次完整 worker prompt；不摘要或截斷輸出，也不把材料區當成整份 prompt。main 另外保留原 skill 的票絕對路徑、完整票文、已選測試配方及控制條款。完成後回原 control loop，不更換 Agent／pi 選路或模型。

   ```bash
   node <本skill絕對目錄>/scripts/compose-materials.mjs <清單絕對路徑> implement <task-id> > <本次材料區檔>
   ```

   如果缺檔、空檔、task 不符或組稿失敗，就不送該輸出，也不復用上一份輸出；main 補齊來源或按原路準備完整 prompt，記下原因。這是受信任本機文件的讀檔器，不驗清單語意完整性、批准狀態或惡意路徑，也不生成 review 材料。完成條件：實際組稿命令成功且原文已交付，或原路降級原因與完整 prompt 可查；兩種情況都保留原派工契約。
4. **記實際工夫。** 如果本次用了或嘗試這條路，就在派工後、返回 frontier 前讀 `~/Desktop/projects/.claude/trials/active.md` 的 `context-preparation-offline` detail 指針，核對身分後在該 detail 的「自然任務觀察」新增或更新本任務一行：`任務／來源路徑｜首次準備動作｜實際省掉的動作｜維護、同步或補送`。不猜分鐘、不每次派工另開一筆，不把 authoring 測試算自然使用。完成條件：每個受試任務有一行可追溯觀察；若 detail 已結案或不可得，就回報、不自行重開 trial。

Review 沿用現有日期：省下重複整理且維護沒有吃掉方便才保留；更費事或反覆漏料就撤接點；零使用或沒有重用機會寫「收益未驗證」，不湊樣本。審查入口不在本次 trial。
