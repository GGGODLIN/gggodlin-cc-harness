# 回歸收尾

適用條件：本批已由使用者選擇 `testing_mode=regression-closeout`。每票的 `required` 仍表示要留下測試；`waived` 仍保留核准的封閉理由。這條路不載入完整 TDD skill；所需品質指引是獨立檔案，不包含另一條路的執行配方。

1. 讀已批准的驗收、公開測試邊界與回歸保護範圍。預期值來自規格／已確認範例，不從目前輸出反推；未定的預期回到既有需求確認，不把猜測寫成測試。
2. 實作並驗收功能。照跑既有單一測試檔、型別檢查與票的實跑驗收。遇到真實錯誤或必要驗收案例時，可直接留下可重複執行的測試，不為了延到收尾而重寫一次性腳本；這不代表改換本批模式。
3. 如果本票需要測試，就在開始補回歸測試前讀同一配置 repo 的 [tests.md](/skills/tdd/tests.md)；如果涉及 mock，就在決定 mock 邊界前讀 [mocking.md](/skills/tdd/mocking.md)。只讀這些品質檔，不呼叫 `Skill(tdd)` 或讀它的 SKILL.md。
4. 功能與預期確認後，補已同意需維持的公開行為與本次真實錯誤案例。不固定實作細節或今天的 bug，不擴寫未批准的範圍。當後續票仍會改變該行為時，先在既有 Verification Log 記下未定項，等該行為確認後補；本批進最後 review 前，required 票的保護範圍都要有測試與實跑結果，未定項不能默認豁免。
5. 跑受影響的最近單一測試，核對預期來源與可觀察行為。對刻意改壞的檢查只在具體疑點需要時採用，不普遍強制；通過只證明這次檢查，不保證規格或所有預期都正確。
6. 把驗收／補測結果、未定項與實際返工回報 controller，由它追加既有 Verification Log；worker 不改票 Status 或共用紀錄。測試補齊後回 implement 的共用 closeout，保留全套件一次、code review、review-implement 與原交付限制。不宣稱本模式比 TDD 更快、更省或更安全。
