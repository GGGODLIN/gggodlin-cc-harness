# 對齊理解

把「你能理解我的意思嗎？」變成可檢查的理解，而不是一句「懂了」後自行開工。重述、列假設、沒有發現差異，都不等於使用者已確認或授權。

## 入口

- 使用者可用 `/align-intent` 或自然語言叫用，不需要參數，也不必先證明哪裡錯。
- 保留模型與既有機制的呼叫能力。機制叫用時先帶齊：原任務、原話或可讀位置、具體分歧、受影響的下一步與返回點。只有「可能沒對齊」不足以啟動；缺少材料就交回呼叫方，不自行補造。
- 這份 skill 不替任何流程新增固定關卡；呼叫方必須明確接線。已在對齊同一件事時沿用當輪，不遞迴叫自己。

## 做法

1. **停在理解層。** 暫不啟動新的實作、派工或對外動作；先辨識這次是使用者直接叫用，還是機制交入。既有背景工作若未確認停止，就如實說仍在跑，不把「暫不做新動作」說成全部已停。

2. **回讀，再重述。** 從當前對話與已給材料找出使用者要的結果、關鍵限制，以及最近的修正。用短句說「我的理解是……」，把使用者原話與自己的推測分開；提及差異時指出對應原話或位置。不要要求重講已有資訊，不為了對齊擴搜個人歷史。原文不可得就標未知，不假裝已核對。

3. **只處理影響下一步的缺口。** 能從材料修正的就先修正自己的理解；仍有會改變目標、範圍或授權的歧義，才問最關鍵的一題並等答案。不把推測寫成「你已選擇」，也不以「有錯請糾正」取代這次必要的確認。不固定列三項、不硬找常見錯誤、不猜使用者的隱藏動機；未發現差異就寫「目前未發現差異」，不宣稱雙方已對齊。若後續回答揭露另一個承重缺口，再釐清，不為遵守一題而跳過它。

4. **交還控制。** 簡短回報「目前理解／修正或仍缺的資訊／下一步停或返回」，無內容的欄位省略。
   - 使用者直接叫用：回報後停住；只有本次已明確授權對齊後續做，且修正沒有超出該授權時才續做。問「理解嗎」不是執行授權。
   - 機制叫用：把修正與未解缺口交回指定位置，由原流程依既有授權繼續或等待，不替呼叫方選顧問、派工、改稿或擴權。
   - 修正使舊計畫失效：指出哪個下一步不能照舊，停在那裡等決定；不偷偷換案，也不硬接原計畫。

以「使用者能指出理解哪裡不對、下一步沒有越權」結束，不以模型自評理解充分結束。這是對話指引，不是攔截工具或取消背景工作的機械保證。
